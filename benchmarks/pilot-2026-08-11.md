- 主机：当前开发主机，非隔离环境。
- 场景：`mixed`，单线程，固定 seed 42。
- 时长：每种实现 3 秒，单样本。

## 首轮发现

传统 auditd 收集到 1,313 条 `SYSCALL` 记录，而 auditd-ebpf stdout 为 0。定位结果是：

1. `run` 未把已存在的 `KernelFilterPlan` stage 到 Aya maps；
2. RingBuf collector 只增加消费计数，未进入用户态规则匹配和 formatter；
3. 内核 header 的 sequence 尚未形成全局唯一 event ID。

本里程碑已接入启动前规则编译/staging、syscall 反向名称解析、用户态精确规则匹配、
单行 formatter 输出和用户态唯一序号。修复后 2 秒 Aya 预检输出 1,160 条事件。
随后接通 `ExecAttempt/ExecResult/Syscall` 关联；真实内核测试确认 `argc=3` 且完整输出
`a0`、`a1`、`a2`，105 条短时事件中 event ID 重复数为 0。collector 线程还改为在生命
周期内持有 stdout 锁，减少逐事件全局锁开销。

## Operation ID 复测

workload 使用固定 15 字节 marker：syscall 通过 `PR_SET_NAME` 写入 `comm`，path 写入
专用目录文件名，exec 写入 argv。规范化器在显式字段缺失时从 `comm`、PATH 或 argv 推导。

2026-08-11 的 1 秒 mixed 双实现复测结果：

- auditd 可观察到 1,511 个唯一 operation ID；
- auditd-ebpf 可观察到 1,589 个唯一 operation ID；
- auditd-ebpf event ID 重复数为 0；
- 两轮 workload 分别完成 2,159 和 2,270 个操作，失败数均为 0。

数量差异来自短时独立运行中实际完成操作数不同，不作为覆盖率结论。完整门禁仍须按同一轮
workload 的期望集合分别核对，而不能直接比较两轮绝对事件数。

因此 T097–T100 保持未完成。
