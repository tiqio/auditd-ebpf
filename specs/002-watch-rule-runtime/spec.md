# Feature Specification: Watch 规则端到端运行

**Feature Branch**: `[002-watch-rule-runtime]`

**Created**: 2026-08-11

**Status**: Draft

**Input**: User description: "分析并调整当前实现，使 `-w /tmp/ddtest -p rw -k ddtest` 不仅能够通过规则检查，还能在实际运行时正确采集并输出文件读写审计事件。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 使用 legacy watch 规则审计文件读写 (Priority: P1)

系统管理员使用熟悉的 audit watch 规则监控指定文件，希望读取或写入该文件时能够得到带有规则 key、目标路径、权限类别和结果的审计记录，而不是仅看到规则语法检查成功。

**Why this priority**: 这是当前功能缺口的直接表现，也是项目能够替代常见 auditd 文件监控场景的最低可用条件。

**Independent Test**: 加载 `-w /tmp/ddtest -p rw -k ddtest`，分别执行一次确定性读取、一次确定性写入和一次无关文件操作；前两者产生符合权限类别的记录，无关操作不产生 `ddtest` 记录，即可独立证明该故事成立。

**Acceptance Scenarios**:

1. **Given** `/tmp/ddtest` 存在且规则 `-w /tmp/ddtest -p rw -k ddtest` 已完整生效，**When** 获准测试进程读取该文件，**Then** 系统在 10 秒内输出一条 `key=ddtest`、目标路径为 `/tmp/ddtest` 且权限包含 `r` 的审计记录。
2. **Given** 同一规则已完整生效，**When** 获准测试进程写入或截断该文件，**Then** 系统在 10 秒内输出一条 `key=ddtest`、目标路径为 `/tmp/ddtest` 且权限包含 `w` 的审计记录。
3. **Given** 同一规则已完整生效，**When** 进程只访问未被监控的其他文件，**Then** 系统不得输出 `key=ddtest` 的审计记录。
4. **Given** 同一操作同时具有读写语义，**When** 进程以读写方式打开目标文件，**Then** 输出记录必须明确表示其匹配的权限集合，不得随机归类或漏掉其中一个已声明权限。

---

### User Story 2 - 在启动前确认 watch 规则确实可执行 (Priority: P2)

系统管理员在启动或重载服务前检查规则时，希望看到 watch 权限对应的运行覆盖范围，并在当前环境无法可靠执行规则时立即得到拒绝和可操作原因，避免“检查成功但运行时永远没有事件”。

**Why this priority**: 静默接受不可执行规则会造成不可见的审计盲区，其风险高于明确拒绝启动。

**Independent Test**: 对有效和故意构造的不可执行 watch 规则分别执行规则检查；有效规则显示非空覆盖摘要，不可执行规则导致整个候选规则集失败且指出文件、行号和原因。

**Acceptance Scenarios**:

1. **Given** 一条合法 watch 规则，**When** 管理员请求规范化检查结果，**Then** 结果显示路径、权限、key，以及每个权限均具有非空运行覆盖。
2. **Given** 权限为空、包含非法字符或无法映射到任何受支持操作的 watch 规则，**When** 启动或检查规则，**Then** 系统拒绝整个候选规则集，不得以空采集计划继续运行。
3. **Given** 当前规则版本正在运行，**When** 重载候选 watch 规则验证失败，**Then** 旧版本继续完整生效并输出明确的重载失败诊断。

---

### User Story 3 - 识别无法可靠归类的文件操作 (Priority: P3)

安全运维人员需要区分“没有发生匹配事件”和“事件发生但系统无法可靠关联路径或权限”，并能够通过状态记录和累计计数发现 RingBuf、用户队列、路径关联或权限归类造成的审计缺口。

**Why this priority**: 文件审计无法保证绝对不丢失时，缺口必须可见，才能支持告警、容量调整和风险处置。

**Independent Test**: 注入路径上下文缺失、描述符关联失效和缓冲区满三类故障，验证每类故障都产生可关联诊断、非零累计计数和降级状态，且不会输出伪造的成功匹配记录。

**Acceptance Scenarios**:

1. **Given** 候选操作可能与 watch 规则相关但路径或权限无法可靠确定，**When** 系统处理该操作，**Then** 系统输出可关联 gap、增加对应缺口计数并进入降级状态。
2. **Given** 事件在任一缓冲或输出阶段被丢弃，**When** 下一次状态记录产生，**Then** 状态包含单调递增的丢失计数，不得把丢失解释为零或正常无事件。
3. **Given** 无新增缺口持续达到既定恢复窗口，**When** 系统恢复健康，**Then** 累计计数保持不清零，状态转换可被运维人员追溯。

### Edge Cases

- 目标文件在规则加载后被删除、重新创建或替换时，系统继续按当前声明的命名空间词法路径匹配，并不得宣称 inode 身份连续。
- 符号链接、硬链接、bind mount、chroot、pivot_root、setns、unshare 或 mount namespace 变化导致路径身份不确定时，系统输出 gap，而不是猜测路径。
- 相对路径、通配符、父目录跳转、空路径或根目录级 watch 不在声明兼容范围时，规则检查必须明确拒绝。
- 同一次操作同时匹配多条规则时，结果必须遵循文档化且稳定的规则顺序，不得因并发或重载随机选择 key。
- 读取、写入、执行或属性修改操作失败时，只要目标和权限能够可靠确定，记录仍应包含失败结果，不能只记录成功操作。
- 文件描述符被复制、继承、关闭或编号复用时，后续操作不得错误关联到旧文件；无法可靠区分时必须形成 gap。
- 兼容进程与宿主进程使用不同 ABI 时，权限语义和输出字段必须一致。
- 高事件率下出现 RingBuf 或用户队列耗尽时，系统不得阻塞被审计业务，必须按既定策略丢弃并计数。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 接受绝对路径形式的 legacy watch 规则 `-w PATH -p PERMISSIONS -k KEY`，其中 `PERMISSIONS` 由一个或多个不重复的 `r`、`w`、`x`、`a` 组成，每条规则必须且只能包含一个非空 key。
- **FR-002**: 系统 MUST 为每条 watch 规则生成非空且可检查的运行覆盖；任何权限无法映射到声明支持的文件操作时，MUST 拒绝整个候选规则集，禁止以空覆盖计划启动或重载。
- **FR-003**: 系统 MUST 按文件操作的实际语义将候选事件归类为读取、写入、执行或属性修改；一个操作可以同时属于多个权限类别，规则在声明权限与事件权限存在交集时匹配。
- **FR-004**: 系统 MUST 发布版本化的 watch 权限兼容矩阵，逐项列出每个权限类别覆盖的文件操作、参数条件、成功与失败行为、支持 ABI 和已知限制；未列入矩阵的操作不得被默认为已覆盖。
- **FR-005**: 系统 MUST 在进程自身 root、mount namespace、当前工作目录和目录描述符边界内解析目标路径，并使用解析后的规范化绝对路径执行 watch 匹配。
- **FR-006**: 对通过文件描述符访问目标文件的受支持操作，系统 MUST 维护足够的进程级关联，使描述符复制、继承、关闭和复用后仍能正确匹配；无法可靠关联时 MUST 形成 gap，不得沿用过期路径。
- **FR-007**: 系统 MUST 对能够可靠识别目标和权限的失败操作生成审计记录，并在记录中明确标识失败结果和退出状态。
- **FR-008**: 每条 watch 命中记录 MUST 包含稳定事件标识、时间、host、machine_id、规则 key、规则版本、进程身份、目标路径、操作名称、匹配权限集合、成功状态和退出状态；无法可靠获得的非关键字段 MUST 明确为未知或缺失。
- **FR-009**: 系统 MUST 保持规则文件顺序和规则内顺序的确定性；同一候选操作匹配多条规则时，MUST 使用文档化的稳定优先级并防止同一规则产生无解释重复记录。
- **FR-010**: 规则检查的规范化输出 MUST 显示 watch 路径、权限、key 和非空运行覆盖摘要，使管理员无需启动服务即可发现不可执行规则。
- **FR-011**: 启动和重载 MUST 先完整验证 watch 语法、权限覆盖、路径边界和资源需求，再一次性应用候选规则；任一验证失败时不得部分生效。
- **FR-012**: 系统 MUST 记录候选事件数、watch 命中数、按权限分类的命中数、路径关联缺口、权限分类缺口、内核缓冲丢失、用户队列丢失和输出失败，并保持累计计数单调不减。
- **FR-013**: 当路径或权限无法可靠确定、事件丢失或计数不变量被破坏时，系统 MUST 在 10 秒内进入降级或不健康状态，并输出可关联到规则版本和故障阶段的诊断。
- **FR-014**: 系统 MUST 保持现有 stdout 审计事件、stderr 状态与诊断、journal 查询和 rsyslog 转发契约；watch 支持不得引入额外日志行、字段注入或下游格式分叉。
- **FR-015**: 系统 MUST 提供可重复的特权正确性负载，至少覆盖 `r`、`w`、`rw`、`x`、`a`、失败操作、无关路径、描述符复制/继承/复用和规则重载。
- **FR-016**: 系统 MUST 提供 watch 功能启用前后的资源对照证据；新增覆盖不得绕过现有性能报告的正确性前置条件，也不得在存在未解释漏报、重复或误报时声明性能收益。

### Security & Audit Data Requirements *(mandatory)*

- **SR-001**: watch 功能 MUST 沿用项目已批准的最小 Linux capabilities、durable dirty 之前不 attach、初始化完成后降权和 `no_new_privs` 策略，不得为文件关联新增长期高权限。
- **SR-002**: watch 功能本身不新增 exec argv 输出；当 watch 与 exec 规则重叠时，MUST 继续遵守默认原样输出完整 argv、显式截断和全局或按 key 关闭控制。
- **SR-003**: watch 审计记录 MUST 沿用现有 journal、文件、导出和 rsyslog 的访问控制、认证加密、保留期与生产风险接受原则；目标路径可能包含敏感目录名，必须纳入同等保护。
- **SR-004**: 配置无效、覆盖为空、资源耗尽、路径关联失败、权限分类失败、事件丢失和输出失败 MUST 可观测，并按严重度阻止启动、保留旧版本或进入降级/不健康状态。
- **SR-005**: watch 事件 MUST 使用现有版本化事件契约；新增权限字段和值域必须向后兼容，未知权限或未知路径不得伪装成空字符串或成功匹配。

### Key Entities

- **WatchRule**: 管理员声明的文件监控规则，包含目标绝对路径、权限集合、key、来源位置、顺序和规则版本。
- **PermissionCoverage**: 某一权限类别在当前兼容范围内对应的操作集合、参数条件、ABI 范围和已知限制，用于启动前验证和运行时归类。
- **FileOperationCandidate**: 一次可能与 watch 相关的文件操作，包含进程身份、操作、参数、结果、路径上下文和候选权限集合。
- **FileAssociation**: 进程及其文件描述符与命名空间词法路径之间的有生命周期关联；可处于可靠、过期或未知状态。
- **WatchAuditEvent**: watch 规则命中后输出的单行审计事件，关联规则版本、key、路径、权限、操作结果和稳定事件标识。
- **WatchGap**: 候选操作无法可靠完成路径或权限归类时产生的可观测缺口，包含原因、阶段、规则版本和累计计数。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对 `-w /tmp/ddtest -p rw -k ddtest` 的确定性测试，读取和写入场景的预期事件覆盖率均为 100%，未解释重复、误报和漏报均为 0。
- **SC-002**: 对 `r`、`w`、`rw`、`x`、`a`、失败操作和无关路径组成的兼容语料，100% 的支持场景产生预期 key、路径、权限和结果，100% 的不支持场景在启动前被明确拒绝。
- **SC-003**: 管理员从触发目标文件操作开始，能在 10 秒内通过前台 stdout 或服务日志查询检索到对应 watch 事件。
- **SC-004**: 规则检查结果中 100% 的合法 watch 规则具有非空权限覆盖摘要，不存在 `syscalls=` 或等价运行覆盖为空但检查成功的情况。
- **SC-005**: 路径关联失败、权限分类失败以及任一缓冲或输出丢失均在 10 秒内产生非零累计计数和降级或不健康状态，故障注入中静默缺口数量为 0。
- **SC-006**: 在最低支持内核和代表性较新内核上，特权测试对宿主 ABI 与兼容 ABI 的声明场景全部通过，测试结束后不遗留活动采集状态。
- **SC-007**: 在项目定义的文件监控压力负载下，新增 watch 支持不阻塞被审计业务，所有丢弃均可由计数解释；在正确性未达到 SC-001 和 SC-002 时，性能报告必须标记为无效。
- **SC-008**: 新增 watch 支持相对同版本关闭 watch 的基线，审计服务 CPU 中位数增幅不超过 10%，工作负载吞吐下降不超过 2%，每种模式至少保留 5 次有效测量和完整复现信息。

## Compatibility & Privileged Testing *(mandatory for eBPF changes)*

- **Minimum Kernel**: Linux 5.15，与现有项目最低内核一致。
- **Architectures**: 首版支持 x86_64 宿主上的 64 位进程和已声明的 32 位兼容进程；其他架构明确拒绝或报告不支持。
- **Attach Mechanism**: 沿用当前已验证的系统调用进入/退出和进程生命周期采集边界；本功能只扩展 watch 候选覆盖、权限归类和文件关联，不引入无法纳入既有内核矩阵的新型不稳定探针。
- **Fallback Behavior**: 任一声明权限无法可靠覆盖时拒绝候选规则；运行中单事件无法可靠归类时输出 gap 并进入降级，不回退为“匹配全部”或“静默忽略”。
- **Privileged Test**: 在隔离测试主机加载 `-w /tmp/ddtest -p rw -k ddtest`，依次触发读、写、读写、失败访问、无关文件、描述符复制/继承/复用、规则重载和高事件率丢失场景；逐项核对事件、权限、key、规则版本、计数、状态、停止排空与资源清理。

## Assumptions

- 本功能聚焦使已声明支持的 legacy `-w/-p/-k` 输入真正端到端可用，不扩展首版规则子集之外的 audit 控制指令或过滤字段。
- watch 匹配继续采用事件进程命名空间内的规范化词法路径语义；本功能不承诺与传统 audit inode watch、硬链接或符号链接身份完全等价。
- 绝对路径是 watch 规则的最低输入要求；相对路径、通配符和父目录跳转继续视为不支持。
- 已有规则加载、双 generation 原子重载、日志输出、生命周期、健康状态和风险接受机制可复用，本功能不得削弱其保证。
- 权限字符采用传统含义：`r` 表示读取，`w` 表示写入或内容变化，`x` 表示执行，`a` 表示元数据或属性变化；精确操作范围由版本化兼容矩阵固定。
- 性能提升只能在正确性测试通过后声明；本功能的首要目标是消除静默无事件，而不是以减少采集范围换取更好性能数据。
